# 设计说明

这份文档解释**为什么这么设计**，以及几个关键取舍的边界。

## 1. 记忆：三种做法，各自的天花板

| 做法 | 优点 | 天花板 |
|---|---|---|
| 全塞进上下文 | 简单、必定生效 | 越用越贵；超出窗口后开始丢 |
| 索引注入系统提示词 | 零调用成本、必定生效 | 索引是**静态**的，和当前问题无关；条目多了只能按"重要/新鲜"挑 |
| 纯检索（工具调用） | 按需、按问题找 | 需要模型主动查；忘了查 = 失忆 |

本项目把三者拆成三层，各管一段，并给出唯一判据：**「下次还成立吗？」**

- 成立 → 常驻层（少量、稳定、每轮注入）
- 只这一次 → 长尾层（大量、按需检索）
- 只是这几天的进行状态 → 短会话层
- **冲突时以常驻层为准**：它是被确认过的事实，检索层只是记录，可能记错。

## 2. 记忆的写入：为什么用「惊讶度」

新记忆先和已有记忆算最大相似度，取补值作为**惊讶度** `s = 1 − max_sim`，初始权重 `w0 ∝ (1 + s)`。

直觉：**越出乎意料的信息越值得记**。重复说过的同一件事，权重自然低；全新的事实权重高。这样不需要人工标"重要/不重要"。

权重还要按来源区分（用户本人说的 vs 别人说的），否则二手信息会挤掉一手事实。

## 3. 检索：为什么是多路融合

单一信号都不够：

| 信号 | 强项 | 弱项 |
|---|---|---|
| TF-IDF 余弦 | 抓话题 | 换个说法就掉（"喝什么" vs "冰美式"） |
| 字符二元组 | 抓字面、短查询 | 近义改写无效 |
| 图扩散 | 抓"间接相关"（A→B→C） | 需要边质量 |
| 关键词/标签命中 | 抓"同一话题" | 稀疏 |

所以打分是：`0.65·cos + 0.35·lex`，再乘 `权重 × 分区加成 × 关键词加成 × 标签加成 × 抖动`，最后做**编码多样性**衰减（同一结构编码的节点依次 ×0.86 / ×0.72），避免一次检索全是同质内容。

## 4. 遗忘：三条机制一起用

1. **时间衰减** `w(t) = w0·exp(−Δt/τ)`，τ 按等级（core 3650 天 / important 30 天 / normal 7 天）
2. **反刍抑制**：短时间内反复被召回的节点降权（防止一件事刷榜）
3. **容量淘汰**：热库超限按权重下沉冷库，冷库长期零命中清出

为什么要遗忘：**陈旧的记忆会被当成真理**。一个三个月前的偏好，如果永远同权重参与检索，会持续污染回答。

例外：高唤醒写入的「闪光灯记忆」不合并、不淘汰、检索时优先——那类记忆本来就该更牢。

## 5. 情绪：从"回声"到"有来源"

最初版本是"事件 → 加减分"：被夸 +0.18，被怼 −0.22。问题很明显：

> 别人夸六句就能把它顶到 +1.00，骂六句就掉到 −1.00 —— 这说明它**没有抵抗力**，也就没有"自己"。

于是加了**需求缺口**：每个需求有期望值，满意度随时间下降，缺口 = 期望 − 满意度，并持续向下拉心情。

- 即使零事件，缺口也会自己变大 → 状态内生漂移
- 满足一个需求，下一个缺口浮上来（社交满足了，"无聊"更显眼）

边界（写进提示词、也写在这里）：

- **只影响表达**：语气、长短、回复延迟
- **不参与事实判断**：不进检索打分，不改结论
- **不改变"要不要回答"**：被直接问话，无论多蔫都要回

## 6. 调参时踩过的坑（都写进代码注释了）

| 现象 | 原因 | 修法 |
|---|---|---|
| 一夜没人理，心情直接掉到 −1 | 缺口拉动太大 | 单位拉动降到 1/6 |
| 心情永远显示接近 0，"闷"看不出来 | 回归用了**线性减法**，把轻微负值削平 | 改成**指数**回归，缺口能维持稳定负值 |
| 它在"睡觉"却还在累积"没休息够" | 空闲时休息满意度仍在下降 | 空闲 ≥2h 视为睡眠，休息满意度回升 |
| 状态文件被反复重算，日志历史被当成新事件 | 日志只有 `HH:MM:SS` 没日期 | 改成**字节游标**，只读新增行 |
| Python 与调用方算出的节奏倍率不一致 | 两处各写一份公式 | 只保留一个公式，两处引用 |

## 7. 不做的事

- 不做六维驱力/决策抽样/世界模拟：对"回答问题"是负资产，只增加复杂度和成本
- 不做 LLM 巩固：确定性规则可复现、可测试、零成本；接 LLM 作为可选增强
- 不声称有主观体验
